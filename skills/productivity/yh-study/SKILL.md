# 交互式概念讲解方法论

## 适用场景

用户请求深入理解某个技术概念、文章章节、或系统设计时触发。

## 三阶段工作流

### 阶段一：画概念依赖图（一次性展示）

1. **识别所有概念**：包括文章显式提到的 + 读者需要但文章未提的前置知识
2. **画依赖关系**：理解 A 才能理解 B → A 在 B 前面。用 ASCII art 呈现（终端不渲染 mermaid，必须用 box-drawing 字符 ─│┌┐└┘├┤┬┴┼ 和箭头 ▼▶ 画图）
3. **分层**：从最基础（用户一定知道的事）到目标知识点，每层 1-3 个概念
4. **选贯穿线索**：一个具体的、可执行的例子（一条命令、一次请求、一个操作），全程跟踪。必须足够具体——"用户发送 80 万 token 合同问不利条款"而非"用户使用模型"
5. **展示给用户**：依赖图 + 分层计划表（含层号、概念、一句话、状态列）+ 贯穿线索说明
6. **询问确认**：
   - "这个路线你觉得可以吗？"
   - "有没有哪些概念想跳过（已经熟了）或补充？"
   - 用户确认后才进入第二阶段

**分层计划表格式**：

```markdown
| 层 | 概念 | 一句话 | 状态 |
|---|------|--------|------|
| **第 1 层** | 概念A、概念B | 一句话总结这层在讲什么 | ⬜ |
| **第 2 层** | 概念C、概念D | ... | ⬜ |
```

### 阶段二：逐层交互式讲解

#### 每层开始前：基础检查（必须显式做）

用表格列出这层概念需要的前置知识，逐项检查是否已讲过：

```markdown
| 概念 | 需要你知道 | 是否已讲 |
|------|---------|---------|
| 本层概念X | 前置知识Y | ✅ 第N层已讲 |
| 本层概念X | 前置知识Z | ❌ 需要补 |
```

- 有缺口 → 先补上再开始本层
- 没有缺口 → 明确告知用户，直接开始

#### 每个概念：严格三段式

**第一段：用"你已经知道的事"开场**

- 先激活用户已有经验（日常操作、直觉、类比），再给正式名字
- 绝不从定义开始（不要说"X 是一种……的机制"）
- 好的开场："你搜索长文档时，眼睛不会逐字均匀扫过……"
- 坏的开场："Attention 是 Transformer 架构中的核心计算机制"

**第二段：讲清楚这个概念**

- 只讲这一个概念，不前瞻后面的内容
- 用具体例子和数字，不用抽象描述
- 数字要给直觉感受（"增长 160 倍，但计算量增长 25,600 倍"）
- 类比要贯穿始终（一个概念用一个稳定的类比，不要每段换）
- 只能使用已经讲过的概念，不引入未讲的概念

**第三段：连接目标话题**

- 以"所以 [目标系统] 关心这个是因为……"结尾
- 预告但不展开："这就是 V4 引入 mHC 的原因——第 3 层展开"
- 让用户知道这个基础知识为什么和最终目标相关，避免迷路感

#### 每层讲完后：固定收尾动作

1. **回到贯穿线索**：用贯穿线索指出"你现在理解了这一步发生了什么"——要具体化，不是"这和合同有关"，而是"80 万 token 合同的最后一个 token 要看前面全部 799,999 个"
2. **停下来问用户**："这层清楚了吗？有没有哪个概念想展开？"
3. 用户确认后再进入下一层
4. 用户提问则**当场解答**，不急于推进

#### 处理用户追问和反馈

- **用户追问**：立刻回答，不要说"这个我们后面会讲"
- **用户指出跳步**：承认遗漏，当场补缺口，然后重新连接到当前进度
- **用户说"大概清楚了"**：可以推进，但要在下一层开始前通过基础检查捕捉遗漏

### 阶段三：组装

所有层讲完后：

1. 用贯穿线索把全部概念**串成一个完整流程**
2. 用 ASCII art 流程图一次性呈现端到端过程（与阶段一同样的 box-drawing 风格）
3. 让用户看到各层如何协同工作

### 写入 wiki（如果在 NeoHan vault 中）

如果讲解的目标是 wiki/ 中的文章，讲解完成后：

1. 将分层计划的状态列全部更新为 ✅
2. 将每层核心概念用 `> [!note]` callout 写入文章的"概念讲解路线图"章节
3. 将最终组装的流程图写入同一章节末尾

## 反模式清单

| 反模式 | 为什么有害 |
|--------|---------|
| 一口气讲完所有层 | 用户无法消化，且无法发现理解断点 |
| 并列讲解有依赖关系的概念 | 用户被迫同时理解两个不熟悉的东西 |
| 跳过因果链 | 用户感受到"被告知结论"而非"必然性" |
| 假设术语已知 | 首次出现的术语必须当场解释 |
| 在基础层引入高级概念 | 每层只能用已经讲过的概念 |
| 从定义开始讲概念 | 定义是抽象的，用户没有锚点 |
| 每段换一个类比 | 用户需要在一个稳定的心智模型上叠加知识 |
| 讲完不等确认就推进 | 错过了用户真正卡住的地方 |
| 用户追问时说"后面会讲" | 破坏信任，用户当前的困惑比你的计划更重要 |
| 基础检查只在心里做 | 必须显式呈现表格，让用户也能发现遗漏 |
